## 二次优化建议（按优先级排序）

### P0 — 用户首次体验关键路径

| # | 建议 | 说明 |
|---|------|------|
| 1 | **对话历史持久化** | 当前 App 重启后所有聊天记录丢失。用户最基本期望是历史消息不丢失。需实现本地持久化（SQLite/文件），启动时加载历史 |
| 2 | **自动重连后恢复会话** | 网络断开重连后，当前对话应自动恢复，无需用户手动操作 |
| 3 | **多窗口/多会话支持** | 当前只能一个对话。用户可能想同时与多个 Agent 对话 |

### P1 — 核心体验提升

| # | 建议 | 说明 |
|---|------|------|
| 4 | **Markdown 渲染增强** | 当前 MarkdownRenderer 基础渲染，缺少代码块语法高亮、表格、LaTeX 公式等。AI 回复中大量代码，无高亮体验差 |
| 5 | **消息搜索** | 聊天记录多了之后需要搜索能力。需先有持久化才能实现 |
| 6 | **拖拽发送文件** | 当前文件发送需点击按钮选择，支持拖拽到输入框或聊天区域更自然 |
| 7 | **快捷键完善** | Cmd+N 新对话、Cmd+, 设置、Cmd+F 搜索等 macOS 标准快捷键 |

### P2 — 功能完善

| # | 建议 | 说明 |
|---|------|------|
| 8 | **订阅管理页实现** | 当前是"即将推出"占位页。如近期不做可先移除入口，避免用户困惑 |
| 9 | **高级设置页实现** | 同上，当前为占位页。可先实现主题切换（深色/浅色/跟随系统）、字体大小调节等基础项 |
| 10 | **Agent 对话上下文管理** | /compact 命令存在但效果不透明，可增加上下文使用量可视化（token 计数器） |
| 11 | **多语言支持** | 当前 UI 全中文，如需面向国际用户需 i18n |

### P3 — 工程与安全

| # | 建议 | 说明 |
|---|------|------|
| 12 | **Token 安全存储** | 当前 token 存 UserDefaults（明文），应改用 Keychain |
| 13 | **daemon API 访问控制** | 当前 daemon 的 HTTP API 无认证（配对后任何本地进程可访问），应增加 access token 验证 |
| 14 | **单元测试覆盖** | Swift 端测试较少，核心链路（消息解析、连接管理、状态管理）应有测试保障 |
| 15 | **CI/CD** | GitHub Actions 自动构建 + 测试 + DMG 打包，减少手动操作 |
| 16 | **Crash 收集** | 接入崩溃收集（如 Sentry 或自建），了解线上问题 |

### P4 — 差异化体验

| # | 建议 | 说明 |
|---|------|------|
| 17 | **Agent 工作流可视化** | 展示 Agent 的思考过程、工具调用链，让用户理解 AI 在做什么 |
| 18 | **语音输入** | macOS 原生 Speech 框架，语音转文字发送 |
| 19 | **快捷指令/Shortcuts 集成** | 让用户通过 macOS Shortcuts 触发 Agent 对话 |
| 20 | **Widget/菜单栏增强** | 当前 MenuBarManager 基础，可增加快捷对话入口 |

## 建议的二次优化路线图

**Phase 1（体验基础）**: 对话持久化 + 自动重连恢复 + Markdown 代码高亮
**Phase 2（效率提升）**: 消息搜索 + 拖拽文件 + 快捷键 + Token Keychain
**Phase 3（功能完善）**: 订阅/高级设置实现 + daemon API 认证 + CI/CD
**Phase 4（差异化）**: Agent 工作流可视化 + 语音输入 + Shortcuts

## 当前已知限制

1. **对话不持久化** — App 重启即丢失所有聊天记录
2. **订阅管理** — 占位页，标注"即将推出"
3. **高级设置** — 占位页，标注"即将推出"
4. **daemon 无 API 认证** — 配对后本地任何进程可访问
5. **Token 明文存储** — UserDefaults 而非 Keychain
6. **单窗口单对话** — 无法同时与多个 Agent 对话
7. **Markdown 渲染基础** — 无代码高亮、无表格、无 LaTeX
